# Runtime and portability

Run inside ChatGPT Work/Codex with the user's connected Workspace, filesystem/script execution, actual fresh subagents and native image-generation capability. Do not use Gumloop, Slack, a paid hosted API branch, an OpenAI API key or an external image provider. This package is instructions and validators for the host, not a standalone inference server or a promise that every AI platform supports the required capabilities.

Resolve IDs from tool readback. A supplied approved outline fills `chapter_blueprint_doc_id`; a supplied approved research package fills `deep_research_doc_id`. These names preserve worker input compatibility; they do not run upstream stages. Accept exact source citations/locators and unresolved gaps; do not invent missing inputs. Scope access to the authorized account, run and inputs.

Use the available Google Drive entrypoint and Google Docs/Sheets skills. Native Docs authoring should follow the host's current supported conversion/editing contracts. Old tool labels in bundled style/reference text are historical examples, not a requirement to install those integrations. Preserve actual native formatting after conversion and re-read it. Text or HTML self-counts are not native presentation proof.

Resolve all bundled role-relative references from that role directory. Resolve `installed/...` roots from this skill root. Historical profile baseline ID/revision are immutable provenance for the bundled presentation profile; another account does not need access to the original private sample. Never reuse the original book's live documents, account settings or output destinations.

Model dispatch: Chapter Writing and its targeted prose revisions = gpt-6-sol medium; controller, Selector, Adapt, Render controller, installed Review, generated evaluator, unified verifier, clean evaluators and placement = gpt-6-sol low. Configure actual host controls with fork_turns none; labels in a prompt are insufficient. A native image model invocation occurs inside Render, not as a different text-role model. Record task IDs/settings; do not expose private reasoning or claim OS-level isolation.

Use the complete installed article-section rules, assets and validators. Full-pipeline authorization includes Adapt's internal handoff-to-Render, while the final human image decision remains mandatory before placement. No LinkedIn caption/signature or author portrait is added to book figures merely because a legacy package name contains LinkedIn.

Maintain a Logs workbook with tabs Run State, Artifacts, Activity & Usage, Decisions and Events. Maintain a Resume Record containing the same JSON snapshot plus exact locators. Inspect tab schemas before writing ranges. Reconcile disagreements rather than choosing a convenient version. There are no hardcoded spreadsheet, account, reviewer or output-folder IDs in the runtime setup.
