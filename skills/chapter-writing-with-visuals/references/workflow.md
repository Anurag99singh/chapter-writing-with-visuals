# Standalone order and acceptance

## 1. Chapter Writing first

Bind approved outline and evidence IDs/revisions to the run. Execute the existing integrated worker: full storytelling-article argument development -> full anshul-writing-style write/format/internal ai-humanizer-core -> storytelling integrity review -> actual native presentation validation. Preserve the bundled voice, craft and typography references. Create A plus Notes/Handoff/Summary. No visual review input is required here.

Run the report-only clean evaluator with `node_name: chapter_writing`, threshold 0.85 and all hard execution/presentation gates. The evaluator rechecks actual prose and native formatting and binds its report to A's exact final revision. A failed check routes to targeted revision and fresh evaluation, maximum three diagnosis attempts per review cycle. A passing A proceeds automatically to generation; there is no new mandatory A approval gate. An explicit user stop still takes precedence.

## 2. Generate from the finished chapter

Read `workers/visual-generation/SKILL.md` and all its required references. Make the generation plan from A's actual sections and paragraphs and approved evidence. Preserve subsection order and internal IDs. Explain why each subsection needs or does not need a visual. Do not force visual density, generate extra research or fabricate a source-review document.

For each YES target, choose the existing DATA/TOPIC/HUMOUR mode with the unchanged scoring and tie-break rules. Run the full pinned installed Adapt, Render and Review packages. Every candidate has separate fresh contexts for Adapt, Render, installed article Review and generated-image evaluation. The renderer sees only that candidate's brief/bound evidence, not other candidate conversations. Automatically load the pinned reference images and design assets; no manual user upload is normally needed. Native image generation only.

Run installed article review before generated evidence evaluation. The latter retains threshold 0.90 and its hard-fail rules. DATA_LOCK numbers/labels/units/caveats must match. Reject the whole failed attempt; maximum two complete render attempts across both gates. Never patch a failing image with text overlays to claim acceptance. Persist each asset/attempt separately and bind receipts to exact asset hashes and A/evidence revisions.

Create and evaluate a GEN-only Unified Visual Review, threshold 0.95. Cover every subsection including explicit NO reasons and exhausted failures. A required target that exhausted attempts is a visible gap: block release until the author explicitly acknowledges omission or requests a new bounded review cycle. A zero-candidate review is valid only when a verified plan explicitly marks every subsection NO.

## 3. Human image gate

Show the actual passing images with their evidence basis. All new candidates begin PENDING. Wait for exact KEEP/EXCLUDE for every current GEN ID. Apply decisions without re-rendering. Verify exact candidate set, review ID/revision, A revision and selected asset hashes. Comments are not approvals. A changed A, evidence, image or review requires revalidation; no inherited decisions on stale candidates.

## 4. Placement and final chapter

Run a fresh Visual Placement role using passing A and resolved current review. Create B separately, remove Notes/Handoff/Summary and add only exact KEEP images with sequential figure numbers, evidence attribution and alt text. No second voice/style pass and no image generation/extraction. Failures to fetch/insert a kept image are recorded precisely and block completion until resolved or explicitly acknowledged; never substitute.

Run clean evaluator with `node_name: chapter_writing_final`, threshold 0.90. Compare all reader prose and native formatting against A and account for every candidate. Produce a separate report. Only passing current B can be offered for final human approval. Keep final approval bound to exact B ID/revision. User-visible output is B; A and audit reports remain separately accessible.

## Recovery and state changes

Use the guard's next action from the exact durable snapshot. `in_flight_operation` requires reconciliation before replay. A quota pause requires reconciliation plus an explicitly known reset/release, never an invented time. Recovery does not create approvals, change scopes or rerun passing candidates. Do not start an automation merely because the package is installed.

Outline/evidence changes route back to A; wording/style changes revise A through the writing skills; image-concept changes revise generation and invalidate its decisions; placement/caption-only feedback can revise B without rewriting A. Published versions remain immutable; conversion repairs can update the same unpublished version.
